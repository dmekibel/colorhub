
# Systems Inventor — Second-Order Palette Systems for ColorHub

## 1. The systems view

Every idea in the panel's seven briefs — Merge A's beauty/dispersion engine, Merge B's shrunk lift, Merge C's career trajectory, Merge D's optimal transport, Merge E's role inference, Merge F's group presets — is secretly one pipeline wearing different clothes: **measurement → representation → baseline → objective → selection → explanation**. Measurement turns pixels into a pool (24 colors + area share, already built) or, with segmentation, into a *region* (a shape with a role, new). Representation turns a measurement into something comparable — a swatch book, a hue histogram, a lift vector, an embedding coordinate. Baseline says "compared to what" — peer painters, the whole archive, the painter's own career, or (new) the archive's whole population of *that compositional role*. Objective turns a baseline-relative representation into a score — beauty, uniqueness, harmony, distinctiveness. Selection turns scores into a finite, ordered set — greedy nested construction, so k=5 is a true prefix of k=12. Explanation wraps every output in a confidence badge and an honesty gate before it reaches the client. The single thing David's two new messages add to this architecture is a **new measurement layer that sits upstream of everything else**: segmentation doesn't replace the pool, it subdivides the canvas *before* the pool is built, so every downstream layer — baseline, objective, selection — can optionally be conditioned on "which part of the painting this came from." That's why it's structurally second-order: it doesn't compete with Merge A/B/C/D/E, it *re-indexes* them. A region-conditioned beauty score, a region-conditioned career trajectory, a region-conditioned signature color are the same engines the critics already prioritized, fed a sharper input.

## 2. Segmentation × Palette, deeply

**Design 1 — Region-Role Palette (sky/ground/figure/water/architecture).**
*Mechanism:* Run MobileSAM "everything" mode offline (a grid of point prompts, native onnxruntime not browser WASM) once per cached painting, producing a few to a few dozen class-agnostic masks. Merge near-duplicate/tiny masks by combined color distance and area (an over-segmentation guard — brushwork dabs must not masquerade as "regions"). For each surviving mask, run `extract_pool`-style clustering restricted to its pixels to get a mini-pool, then pick its single most "interesting" color using the already-specified perceived-saturation + archive lift formula (Merge A's own scoring function, just scoped to one mask) rather than its mean. Assemble one palette per painting sampling across regions, not across the whole-canvas area-share pool — this is a literal build of David's message 1 ("the most interesting colors from each segment… placed on a palette").
*Labeling:* math-first, not a learned model, matching David's own stated preference for something that still runs at 42k-image scale: a rule classifier over each mask's geometry (touches top edge → sky candidate; large, contiguous, low internal variance → sky/water candidate), position (upper third vs lower two-thirds), texture (local luminance variance — low for sky/water, high for foliage/figure detail), hue band (blue/white/grey → sky; green/brown → ground; skin-tone hue range + compact vertical aspect ratio → figure), and adjacency (a region sharing a long horizontal boundary with a confirmed sky region is more likely ground/water). Low-margin masks stay "unlabeled" rather than forced into a role.
*Cost at 42k (63k cached images):* the SAM encoder is the expensive step (2.7–3.4s *single-thread browser WASM*, per `js/segment.js`'s own measured numbers); an offline batch would run native onnxruntime-CPU, which is very likely faster but **is not measured anywhere in this repo** — a pilot timing run (Stage 1 below) is required before committing to the full batch rather than extrapolating from the browser number. Output is a new shard family, e.g. `data/analysis/regions-NNN.json`, storing only derived region summaries (label, mini-pool, bbox/contour for UI overlay) — never the raw mask bitmaps, to stay inside the existing static-JSON size discipline.
*User sees:* a new palette mode next to By-area/Diverse/Harmonies — "By scene" — swatches labeled Sky/Water/Figure/Ground, each tappable to a contour overlay on the actual image (reusing the Select tool's existing mask-rendering code).
*Failure modes:* SAM's everything-mode will over-segment textured brushwork (late Monet's dappled water-lily surface could fragment into dozens of near-meaningless masks) and under-segment smooth old-master glazes into one giant undifferentiated blob; the rule classifier will misread a distant blue mountain as sky or a shadowed foreground as water.
*Improved version:* confidence-gate every label (unlabeled regions still contribute colors to the palette, just without an invented role caption) and add the merge-before-classify step described above so brushwork texture never reads as "40 regions."

**Design 2 — The Boundary/Seam Palette.**
*Mechanism:* for every pair of adjacent masks from Design 1, sample a thin pixel band straddling the shared boundary and cluster it separately from either region's interior. Compare the boundary cluster against both interior means: a boundary color that differs from both (above a ΔE floor) is a real "edge accent" (a rim-light, an outline); one that's just a blend of the two interiors is a soft transition, not reported. This is a direct, spatially-grounded fix for the rigor critic's own complaint about the panel's Albers/temperature-interaction idea (Painter #6), which inferred "matched-lightness pairs" from pool-bucket coincidence rather than measuring an actual physical edge.
*Labeling:* none needed for the mechanism — pure pixel math, reusing Design 1's masks for adjacency.
*Cost:* near-free on top of Design 1 — one extra clustering/comparison pass, no new ML inference.
*User sees:* a "seams" view — swatches captioned "where the awning meets the night sky," tappable to the literal strip on the image.
*Failure modes:* a fixed-pixel-band width is scale-dependent (a thumbnail vs. full-res photo have different effective brushwork-to-pixel ratios — the same confound the panel's broken-color idea already flagged), and JPEG compression halos at hard edges can manufacture a fake "accent" that's an artifact, not paint.
*Improved version:* normalize band width to detected brushwork scale (or physical size when known) and require the boundary color to clear a null built from random same-length strips cut well inside each region, so "accent" means "further from both interiors than sampling noise would produce."

**Design 3 — A Painter's Habitual Sky vs. Habitual Ground Across a Career.**
*Mechanism:* feed Design 1's sky-labeled (and separately ground-labeled) regions into the exact machinery that already builds painter swatch books and runs PELT changepoint detection on decade centroids (Merge C), but scoped to one semantic role. Signature-color lift is computed against a *region-specific* global baseline — "this painter's sky" vs. the archive's whole sky-region population, not vs. the archive's whole-painting population — which isolates color choice from composition choice (how much sky a painter happens to paint) in a way nothing in the original panel could do.
*Labeling:* Design 1's classifier, applied at painter × decade granularity, gated by the same density floor (≥10 confidently-labeled sky paintings per bucket) the painter page already enforces elsewhere.
*Cost:* zero new SAM inference — reuses Design 1's output; new work is offline aggregation code and one new global "sky corpus" baseline histogram, built once.
*User sees:* on a painter page, a second, parallel timeline strip under the existing palette-by-decade — "His skies, by decade" — letting a user discover whether a painter's sky stayed constant while their foreground grew more vivid, or moved together.
*Failure modes:* the semantic classifier is the weak link here specifically because it now feeds a changepoint detector — a run of misclassified "sky" regions in one decade bucket could manufacture a fake shift.
*Improved version:* report classifier-confidence per decade bucket alongside the trajectory and suppress any bucket below the confident-sky density floor, exactly the discipline Merge C already requires one level up.

**Design 4 — Cross-Painter "How 20 Painters Painted the Sky."**
*Mechanism:* build one swatch book per (painter × region-role), (movement × region-role), (decade × region-role) from Design 1's masks, then run the already-planned Color-DNA Map (AI-Researcher #2 + Art-Historian's wild idea + Mathematician's PMI graph, as merged by the critics) restricted to one region-role's feature vectors instead of whole-painting vectors — a "sky map" where painters may cluster very differently than on the whole-canvas DNA map.
*Labeling:* same classifier as Design 1/3, now needing to hold up consistently across hundreds of painters — the bar is higher here than anywhere else in this list.
*Cost:* builds on Design 1 plus the existing embedding machinery (cheap at a few thousand region-level vectors).
*User sees:* a cross-cutting browse mode, "Sky, across painters" — a small-multiples grid of 15-20 painters' sky-region swatches, linking into their painter pages.
*Failure modes:* "sky" as a comparison axis implicitly filters to landscape-leaning painters, silently biasing any "most vivid sky" ranking against portraitists and still-life painters who rarely show sky at all; also inherits the digitization-source confound the rigor critic flagged for the whole-corpus manifold.
*Improved version:* always show n (how many sky-labeled works a painter contributes) next to any cross-painter ranking, and frame it explicitly as "painters who paint enough sky to compare," never implying universal coverage.

**Design 5 — Region-Conditioned Beauty/Uniqueness Engine.**
*Mechanism:* a drop-in enhancement, not a new engine — feed the critics' own First-Build survivor (the Confidence-Gated Beauty/Dispersion/Uniqueness Selector) a region-role-specific lift baseline (from Design 4) instead of the whole-archive baseline, whenever a candidate color's source region clears the classifier's confidence floor; fall back to the existing whole-archive baseline otherwise. This is the most literal build of David's message 1: "intelligent analysis" of each segment feeding a still-mathematical selector.
*Cost:* zero new inference — a re-indexed lookup table once Designs 1 and 4 exist.
*User sees:* no new screen — the existing "Striking"/"Signature" palette mode gets sharper selections and a truer explanation sentence ("unusually vivid for a sky passage," not just "unusually vivid").
*Failure modes:* inherits every upstream classifier failure, now compounded into the one engine the critics already flagged as the panel's highest-value survivor — a bad region label doesn't just mislabel a swatch, it corrupts the flagship score.
*Improved version:* require high classifier confidence before switching a candidate's baseline, and log both the whole-archive and region-specific scores during a beta window so a craft-critique pass can audit where region-conditioning actually changed the selected palette.

## 3. Other second-order systems

1. **Era-Signature Palettes** (Career Trajectory × Beauty/Uniqueness Engine). Run the Beauty engine separately *within* each PELT-detected era rather than over a painter's whole career, so "his most beautiful palettes" becomes a per-era finding, not one global palette smeared across a lifetime — this is the literal mechanism behind David's own intuition about van Gogh's "colorful stages," turned into a discoverable property instead of a hand-picked example.
2. **Calibrated-Distractor Odd-One-Out** (Optimal Transport/distributional distance × the existing Odd-One-Out game × Color-DNA Map). Use OT/Wasserstein distance between swatch books (already slated as internal plumbing, never meant to surface as a raw number) to pick plausible-but-wrong distractors for a new round type — "which of these four painters' swatch books doesn't belong" — so the serious math becomes gameplay instead of a dashboard metric, directly serving "learn by seeing" and "game: beauty first."
3. **Era-Dated Design Tokens** (Role Inference/Export Pipeline × Career Trajectory). Export a UI kit from a painter's *detected era*, not a single painting or their smeared career average — "van Gogh's Arles palette as a design system" — distinct from the Movement/Decade Group Presets merge because it's keyed to one painter's own measured shift, not a cross-painter bucket.
4. **Per-Region Pigment-Clock Check** (the surviving falsification-only Pigment Clock × segmentation). Instead of one anachronism check per painting, run it per labeled region — catching a *localized* implausibility (the sky reads anachronistic, the figure doesn't) that a whole-painting check would average away. This is the kind of spatially-specific, still strictly falsifying ("likely later overpaint," never "this is pigment X") honesty feature segmentation uniquely enables.
5. **Spatially-True Mother Color** (the survivor Mother Color Detector × real masks). The panel's original version ranked "which regions carry the tint" only by *color proximity* to a hypothesized tint line — a statistical guess at spatial location. With real masks, this becomes exact: the actual sky, actual drapery, actual skin region can be outlined and ranked by true tint-share, upgrading an inference into a direct measurement.
6. **Grounded Pairing** (the PMI hue co-occurrence graph × region-adjacency). The panel's own color-pair PMI measure can't distinguish true compositional pairing from two hues that both merely appear somewhere on the canvas — exactly the weakness the rigor critic named. Requiring a pair to clear the PMI threshold *and* share a measured region boundary before calling it a "compositional pairing" directly fixes that, using segmentation as the missing spatial evidence.
7. **Broken-Color Index, cheaply unlocked** (the shelved, feasibility-2 Optical-Mixture Index × the SAM masks already being computed for Design 1/2). The original idea needed a bespoke SLIC pass just to get adjacency data; once SAM's masks and boundary data exist anyway, the same small-adjacent-masks/similar-lightness/different-hue test becomes a near-free by-product, moving this from "v2 research project" to "ships alongside Design 1."
8. **Ask the Archive About Just This Part** (the app's already-shipped interactive on-device Select tool × Design 4's offline region fingerprints). When a user taps to select a region live, compare that live mask's color against the precomputed archive-wide region-role fingerprints — "this sky sits at the 80th percentile of vividness among archive skies, closest to [painter]'s skies." Neither the live tool nor the offline corpus alone can produce this; it's genuinely only possible once both exist.
9. **Guess the Region** (Design 1's region-labeled palettes × Odd-One-Out mechanics × the "closeness beats coverage" game principle). A new round type: four swatches, each a real region-color from a different painting, deliberately chosen near the redundancy floor so they're genuinely close — "which is the ground, which is the water" — teaching compositional color roles instead of raw hue discrimination.
10. **Restoration-Pattern Triangulation** (Per-Region Pigment Clock × Spatially-True Mother Color). When a region independently fails the pigment-clock plausibility check *and* carries an unusually strong shared tint relative to the rest of the canvas, that's two weak, independent signals converging on the same location — stronger evidence of later overpaint/restoration than either alone, always framed as "a pattern consistent with restoration," never a claim, and reviewed with real conservation literature before any such language ships.
11. **Composition-Grounded Role-and-Ratio** (Role Inference/Export Pipeline × segmentation). The panel's Role Inference merge assigns Anchor/Primary/Accent purely from area-share and chroma rank, which the rigor critic flagged as conflating "visually prominent" with "appropriate UI role." Grounding the same roles in actual segmented composition — the figure-region's dominant color is Primary because it *is* the compositional subject, not just because it's locally saturated — directly answers that critique with real spatial evidence instead of color statistics alone.

## 4. The engine

```
L0  Raw assets        research/_raw/{source}/*.jpg, museum metadata
L1  Pool measurement   tools/gallery.py extract_pool -> data/gallery/d/NNN.json (24-color pool + share)
L1b Region measurement  [NEW] offline SAM everything + math-first role classifier
                         -> data/analysis/regions-NNN.json (masks' mini-pools, role, bbox, adjacency)
L2  Per-painting stats  data/analysis/paintings-NNN.json (L/C histogram, focal/glue/accent/hidden,
                         findings, nearest-neighbor) -- extended to reference L1b where confident
L3  Group aggregation   data/analysis/groups.json, data/analysis/artists/<slug>.json
                         (signature/avoided + lift, palette-by-decade, change points),
                         data/games/oo/{painter,movement,decade}/*.json swatch books
                         -- extended with [NEW] region-conditioned swatch books + one global
                            per-role baseline histogram (data/analysis/region-baselines.json)
L4  Cross-cutting maps  Color-DNA embedding, PMI hue graph, OT/Wasserstein distance matrix
                         -- each with a [NEW] region-role-restricted variant
L5  Scoring engines     Confidence-Gated Beauty/Dispersion/Uniqueness Selector (flagship,
                         optionally region-conditioned via L1b/L3 = Design 5),
                         Career Trajectory/PELT (optionally per-region = Design 3),
                         Role-and-Ratio/export pipeline (optionally segmentation-grounded = #11)
L6  Honesty layer       shared confidence badge, applicability/density gates -- wraps every L5 output
L7  Static delivery     sharded, versioned (?v=), lazily loaded (js/loader.js), as today
```
Screens: the **painting page** reads L1b (By-scene mode, seams), L2 (role labels), L5 (flagship palette + export), L6 (badges). The **painter page** reads L3 (signature colors, decade strip) and L5's Career Trajectory, now with an optional region sub-strip from Design 3. The **movement/decade page** reads L3's group aggregation and the Merge-F presets. The **color page** reads L4's nearest-neighbor links, now plus "this hue as a sky, as a figure" from the region swatch books. **Games** (Odd-One-Out) read L3/L4's swatch books and distance matrix for calibrated rounds (#2, #9). **Studio/Learn** read the live Select tool cross-referenced against L3's region baselines (#8).

## 5. Taken to its logical conclusion

The ambitious end state: every pixel of every cached painting carries a compositional role, every role has its own statistical universe (its own baseline, its own trajectory, its own cross-painter map), and a user can query the whole corpus along composition × color × time × lineage at once — "skies as vivid as late Monet's, anchors as dark as early Rembrandt's, by painters influenced by Hals." The honest version is narrower: semantic-labeling confidence will be worst on exactly the paintings where this would be most interesting — crowded compositions, abstracted late-Impressionist brushwork, anything without a clean sky/ground/figure structure (portraits, still lifes, most non-landscape genres) — so region-conditioning will likely only clear its confidence floor on a minority of the 42k-painting corpus, probably landscapes, marines, and a subset of figure work. The honest end state is: region-aware systems extend, never replace, the whole-canvas systems already prioritized by the critics; the "unlabeled majority" of the corpus keeps every existing system at full strength, and the region layer ships as a bounded, always-confidence-flagged enhancement, not a universal promise.

## 6. Build order

**Stage 0 (prerequisite, no segmentation).** Ship the critics' own agreed First Build — the Confidence-Gated Beauty/Uniqueness Palette Selector (Merge A+B) — exactly as specified, with its own three-reference-painting + Monet test already defined in the rigor critic's brief. Every region-conditioned system above (Designs 3/5, combo #1) needs this engine to exist before it can be enhanced.

**Stage 1 — Pilot the SAM batch, don't commit blind.** Run offline SAM "everything" mode (native onnxruntime, not the browser WASM path `js/segment.js` measures) on a 200–500 painting pilot spanning landscapes, portraits, interiors, multiple centuries and sources — including the three van Gogh references and at least three Monets (two Argenteuil-period, one late Giverny water-lily). *Falsifiable test:* after the over-segmentation merge step, each test painting should yield roughly 4–15 regions, and at least one mask in each of the four landscapes should visibly correspond to "the sky" on inspection. If Monet's dappled water-lily surface still fragments uncontrollably after merging, that is the falsification signal that Design 1 needs a stronger merge step or must gracefully degrade to "no clean regions found" for that style, per the Stage-3 honesty gate.

**Stage 2 — Validate the classifier before scaling.** Hand-label the same pilot set (David or a curator) for sky/ground/water/figure/foliage/architecture; score the math-first rule classifier against it and report a confusion matrix, not a single accuracy number. *Gate:* the whole region feature only proceeds to full-corpus batch if sky/ground agreement clears a real bar on the pilot; otherwise ship Designs 1–5 only on the confident subset, never archive-wide.

**Stage 3 — Design 1 + Design 5 together.** Region-Role Palette plus the (nearly free) region-conditioned Beauty engine. *Falsifiable test:* run the region-conditioned engine on the three van Gogh references and the Monet set; check whether conditioning changes the selected palette versus the un-conditioned baseline, and whether the new explanation sentences ("unusually vivid for a sky passage") read as truer under craft-critique review than the ungrounded version. If region-conditioning never changes anything because the classifier rarely clears its confidence floor, the feature isn't earning its build cost yet.

**Stage 4 — Design 2 + combo #6 (PMI × adjacency).** Cheap once Design 1's masks exist. *Falsifiable test:* on Café Terrace at Night, does the boundary mechanism surface a real edge accent at the awning/night-sky junction that clears the null-strip comparison (Design 2's improved version), not a compression artifact.

**Stage 5 — Design 3 + combo #1 (Era-Signature Palettes).** *Falsifiable test:* on van Gogh, does the region-conditioned sky trajectory diverge from his whole-painting change-point, coincide with it, or stay flat — any of the three is a valid, reportable outcome; the test is whether the density-gated pipeline produces a *stable* answer at all for a well-documented painter before trusting it on thinner-data painters.

**Stage 6 — Design 4 (cross-painter region fingerprints).** Gated on enough painters clearing Stage 2's density floor. *Falsifiable test:* does Monet land near other Impressionist landscape painters specifically on the sky fingerprint, and does a "most vivid sky" ranking plausibly include Monet or van Gogh in its top decile — reported as whatever the real computation yields, treating a surprising absence as valid data, not a bug to fix until it matches intuition.

**Stage 7 (optional, highest risk) — combo #4/#10, restoration-pattern triangulation.** Held behind an explicit conservation-literate review before any restoration-adjacent language ships, given the standing rigor-critic concern about overclaiming physical history from color statistics alone.

Every stage after Stage 0 is cheap or free once the prior stage's artifacts exist — the real cost and the real risk are both concentrated in Stages 1–2 (does SAM's output and the math-first classifier actually hold up on real paintings at scale), which is exactly where the plan puts the falsifiable gates.
